## Какво прави тази програма?

Симулира работата на малък магазин:

- Имаш **стоки** — хранителни (мляко, хляб) и нехранителни (шампоан, батерии).
- Имаш **касиери**, всеки от тях работи на своя **каса**.
- Клиент идва, дава пари, касиерът го обслужва и издава **касова бележка**.
- Бележката се **записва в текстов файл** на диска.
- Накрая магазинът може да изчисли колко е **спечелил или загубил**.

## Как е наредена папката с проекта?

```
shop-management/
│
├── pom.xml                          ← Конфигурация на Maven (инструментът за build)
│
├── receipts/                        ← Тук се записват касовите бележки като файлове
│
└── src/
    ├── main/java/com/shop/
    │   ├── Main.java                ← Тук стартира програмата
    │   │
    │   ├── model/                   ← Моделите — описват обектите в магазина
    │   │   ├── Product.java         ← Базов клас "Стока"
    │   │   ├── FoodProduct.java     ← Хранителна стока
    │   │   ├── NonFoodProduct.java  ← Нехранителна стока
    │   │   ├── Cashier.java         ← Касиер
    │   │   ├── CashRegister.java    ← Касов апарат
    │   │   ├── Receipt.java         ← Касова бележка
    │   │   └── ReceiptItem.java     ← Един ред от бележката
    │   │
    │   ├── exception/               ← Изключения (грешки)
    │   │   ├── InsufficientQuantityException.java  ← Малко стока
    │   │   └── InsufficientFundsException.java     ← Малко пари
    │   │
    │   └── service/                 ← Действия бизнес логиката
    │       ├── Shop.java            ← Магазинът (пази всичко)
    │       └── ReceiptService.java  ← Записва/чете/сериализира бележки
    │
    └── test/java/com/shop/
        └── ShopTest.java            ← Автоматични тестове
```

> **Прости думи:** `model/` съдържа "нещата" (стоки, касиери и т.н.), `service/` съдържа "действията" (продай, изчисли печалба), `exception/` съдържа "грешките".

## Обяснение на всеки клас

---

### `Product.java` — Базова стока

Това е "шаблонът" за всяка стока. Съдържа:

| Поле | Какво е |
|------|---------|
| `id` | Уникален номер на стоката |
| `name` | Наименование |
| `deliveryPrice` | Колко сме платили при доставка |
| `expiryDate` | Краен срок на годност |
| `quantity` | Колко бройки има в склада |

**Ключови методи:**

- `getSellingPrice()` — изчислява **продажната цена** (виж по-долу).
- `isExpired()` — проверява дали стоката е с **изтекъл срок**.
- `isNearExpiry()` — проверява дали срокът **наближава** (по-малко от N дни).

> `abstract` означава, че класът не може да се използва директно — трябва да го "разширим" с `FoodProduct` или `NonFoodProduct`.

---

### `FoodProduct.java` — Хранителна стока

Разширява (наследява) `Product`. Единственото допълнение е, че **надценката е 30%** (по подразбиране).

```java
FoodProduct milk = new FoodProduct(1, "Мляко", 1.50, LocalDate.now().plusDays(10), 50);
```

---

### `NonFoodProduct.java` — Нехранителна стока

Разширява `Product`. Надценката е **50%** (по подразбиране).

```java
NonFoodProduct shampoo = new NonFoodProduct(3, "Шампоан", 5.00, LocalDate.now().plusDays(365), 20);
```

---

### `Cashier.java` — Касиер

Прост клас с три полета: `id`, `name`, `monthlySalary`.

```java
Cashier cashier = new Cashier(1, "Иван Петров", 1500.00);
```

---

### `CashRegister.java` — Касов апарат

На всяка каса работи **един касиер**. Касата:
1. Получава списък с артикули и парите на клиента.
2. Проверява дали всичко е наред (не изтекло, достатъчно количество, достатъчно пари).
3. Намалява наличностите.
4. Издава и записва **касова бележка**.

```java
CashRegister register = new CashRegister(1, cashier);
Receipt receipt = register.processSale(items, 20.00);
```

---

### `Receipt.java` — Касова бележка

Съдържа:
- `receiptNumber` — пореден номер (автоматично се увеличава).
- `cashier` — кой е издал бележката.
- `dateTime` — кога точно.
- `items` — списък с артикули.
- `total` — обща сума.

Методът `toFormattedString()` връща красиво форматиран текст, готов за запис.

---

### `ReceiptItem.java` — Ред от бележката

Един ред = една стока + количество + единична цена в момента на продажбата.

> Важно: цената се **записва в момента на продажбата**. Дори ако цената на стоката се промени после, бележката пази оригиналната.

---

### `Shop.java` — Магазинът

Главният "мениджър". Пази списъците с касиери, каси, доставени стоки.

**Финансови методи:**

```java
shop.calculateExpenses();  // заплати + стойност на доставките
shop.calculateRevenue();   // сбор от всички касови бележки
shop.calculateProfit();    // приходи - разходи
shop.printFinancialReport(); // отпечатва отчет
```

---

### `ReceiptService.java` — Работа с файлове

| Метод | Какво прави |
|-------|-------------|
| `saveToFile(receipt)` | Записва бележката като `receipt_1.txt` |
| `readFromFile(number)` | Чете и връща съдържанието на файла |
| `serialize(receipt)` | Записва обекта като `receipt_1.ser` (бинарен файл) |
| `deserialize(number)` | Зарежда обекта от `.ser` файл |

## ❗ Изключения (Exceptions)

Изключенията са начинът на Java да каже: **"Нещо се обърка!"**

В нашия проект имаме три вида проблеми:

### 1. `InsufficientQuantityException`
Хвърля се, когато клиент иска повече бройки, отколкото има.

```
Недостатъчно количество за стока 'Мляко' (ID: 1).
Заявено: 999, налично: 50.
```

### 2. `InsufficientFundsException`
Хвърля се, когато клиентът дава по-малко пари.

```
Недостатъчно пари. Необходими: 18.20 лв., предоставени: 1.00 лв.
```

### 3. `IllegalStateException` (вградено в Java)
Хвърля се при опит за продажба на стока с изтекъл срок.

### Как "хващаме" изключенията?

```java
try {
    register.processSale(items, money);  // може да гръмне
} catch (InsufficientQuantityException e) {
    System.out.println("Грешка: " + e.getMessage());
} catch (InsufficientFundsException e) {
    System.out.println("Грешка: " + e.getMessage());
}
```

> `try` = "опитай", `catch` = "хвани грешката ако се случи".

## Сериализация

**Сериализацията** означава: превръщане на Java обект в поредица от байтове, за да го **запишем на диск или изпратим по мрежата**.

**Десериализацията** е обратното — зареждаме обекта обратно от файла.

За да работи, класовете трябва да имплементират `Serializable`:

```java
public class Receipt implements Serializable {
    private static final long serialVersionUID = 1L;
    // ...
}
```

`serialVersionUID` е като "версия" на класа — помага на Java да разбере дали файлът е съвместим.

**Резултат:** файловете `receipt_1.ser`, `receipt_2.ser` и т.н. в папка `receipts/`.

## Тестове

Файлът `ShopTest.java` съдържа **автоматични тестове** с JUnit 5.

Тестът е просто метод, който:
1. Подготвя обект.
2. Извиква метод.
3. Проверява дали резултатът е очакван.

```java
@Test
void testFoodProductSellingPrice() {
    Product milk = new FoodProduct(1, "Мляко", 1.50, ...);
    double expected = 1.50 * 1.30;  // 30% надценка
    assertEquals(expected, milk.getSellingPrice(), 0.01);
}
```

| Анотация | Значение |
|----------|----------|
| `@Test` | Това е тест |
| `@BeforeEach` | Изпълни преди всеки тест |
| `@DisplayName` | Описание на теста |
| `assertEquals(a, b, delta)` | Проверява дали `a ≈ b` |
| `assertThrows(Exception, ...)` | Проверява дали се хвърля грешка |

Пусни тестовете с:
```bash
mvn test
```

## Как се изчислява цената?

```
Продажна цена = Доставна цена × (1 + надценка%)
```

Ако стоката е с **наближаващ срок**:
```
Продажна цена = Продажна цена × (1 - намаление%)
```

### Пример с мляко (доставна цена 1.50 лв.):

```
Нормална цена   = 1.50 × 1.30 = 1.95 лв.
При намаление   = 1.95 × 0.80 = 1.56 лв.
```

### Конфигурируеми параметри

```java
FoodProduct.setFoodMarkupPercent(30.0);       // надценка за хранителни (%)
NonFoodProduct.setNonFoodMarkupPercent(50.0); // надценка за нехранителни (%)
Product.setExpiryWarningDays(3);              // предупреждение N дни преди изтичане
Product.setDiscountPercent(20.0);             // намаление при наближаващ срок (%)
```
